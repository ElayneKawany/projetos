# Project Lifecycle

## Objetivo

Este documento define o ciclo de vida oficial dos projetos dentro da plataforma.

Toda funcionalidade desenvolvida deverá respeitar este fluxo.

O objetivo da plataforma é conduzir um projeto desde a criação da ideia até o acompanhamento dos benefícios após sua implantação.

---

# Estrutura do Ciclo de Vida

O ciclo de vida do projeto é composto por quatro fases principais.

Cada fase possui objetivos, entregas, responsáveis e Gates de aprovação.

Um projeto somente poderá avançar para a próxima fase após a conclusão dos Gates obrigatórios.

---

# Fase 1 - Iniciação

## Objetivo

Formalizar a ideia e validar sua viabilidade antes da autorização para execução.

## Fluxo

Cadastro da Ideia

↓

Triagem PMO

↓

Elaboração da TAP

↓

Aprovação da TAP

↓

Elaboração do Estudo de Viabilidade

↓

Aprovação da Viabilidade

↓

Comitê Executivo

↓

Aprovação para Estruturação

---

# Fase 2 - Estruturação

## Objetivo

Planejar completamente o projeto antes da execução.

## Principais atividades

* Cronograma
* Planejamento Financeiro
* Definição dos responsáveis
* Planejamento das entregas
* Aprovação da Estruturação

---

# Fase 3 - Execução

## Objetivo

Executar todas as atividades planejadas.

## Principais atividades

* Gestão das tarefas
* Controle do cronograma
* Controle financeiro
* Gestão dos responsáveis
* Go Live

---

# Fase 4 - Acompanhamento de Benefícios

## Objetivo

Garantir que os benefícios planejados sejam efetivamente entregues.

## Principais atividades

* Transição para suporte
* Acompanhamento do ROI
* Acompanhamento do Payback
* Medição dos benefícios
* Encerramento do projeto

---

# Gates

Os Gates representam pontos formais de decisão.

Cada Gate deverá possuir:

* Nome
* Ordem
* Responsável
* Status
* Data de criação
* Data de conclusão
* Observações

Os Gates serão configuráveis por empresa.

A plataforma disponibilizará um fluxo padrão que poderá ser personalizado sem alterar a lógica do ciclo de vida.

---

# Responsáveis

Cada Gate possuirá um ou mais responsáveis.

O fluxo padrão servirá apenas como modelo inicial.

Cada projeto poderá definir responsáveis diferentes conforme sua necessidade.

---

# Aprovações

Toda aprovação deverá registrar:

* Responsável
* Data
* Hora
* Parecer
* Observações

Toda reprovação deverá possuir justificativa obrigatória.

---

# Histórico

Toda movimentação entre fases e Gates deverá ser registrada.

O histórico deverá armazenar:

* Usuário
* Data
* Hora
* Ação realizada
* Situação anterior
* Nova situação

---

# Princípio do Produto

A plataforma não é apenas um sistema para cadastro de projetos.

Ela é uma plataforma de Governança de Projetos, responsável por conduzir o projeto desde a ideia inicial até a comprovação dos benefícios obtidos após sua implantação.
