# ESPECIFICAÇÃO FUNCIONAL 002

# Módulo TAP (Termo de Abertura do Projeto)

Versão: 1.0

Status: Em elaboração

---

# Objetivo

O módulo TAP é responsável por formalizar a abertura do projeto.

A TAP representa a primeira documentação oficial do projeto e deverá consolidar todas as informações necessárias para iniciar sua análise.

O usuário nunca editará diretamente o documento Word.

Toda informação será cadastrada através da plataforma.

O documento será gerado automaticamente utilizando o template institucional.

---

# Fluxo

Projeto criado

↓

Usuário seleciona a aba TAP

↓

Preenche formulário

↓

Gerar TAP

↓

Sistema gera documento

↓

Cria versão

↓

Registra histórico

↓

Envia automaticamente para Aprovação

↓

Projeto permanece aguardando aprovação

↓

Após aprovação

↓

Habilita Estudo de Viabilidade

---

# Origem das Informações

A TAP será preenchida através do formulário da plataforma.

O sistema será responsável por gerar automaticamente o documento utilizando o template padrão da empresa.

O documento gerado será armazenado como versão do projeto.

---

# Estrutura da TAP

## Identificação

* Nome do Projeto
* Área Solicitante
* Responsável
* Gerente do Projeto
* Data de abertura

---

## Descrição

* Descrição do Projeto
* Problema ou Oportunidade
* Objetivo
* Escopo Inicial
* Fora do Escopo
* Benefícios Esperados

---

## Stakeholders

Permitir cadastrar múltiplos Stakeholders contendo:

* Nome
* Área

Os Stakeholders cadastrados ficarão disponíveis para reutilização nas próximas etapas do projeto.

---

## Estimativa Financeira

Esta etapa possui caráter exclusivamente estimativo.

Antes da exibição dos valores financeiros, o sistema deverá perguntar:

**Existe uma estimativa financeira para este projeto?**

( ) Sim

( ) Não

Caso o usuário selecione **Não**, nenhum campo financeiro será exibido.

Caso selecione **Sim**, permitir informar:

* Estimativa inicial de CAPEX (opcional)
* Estimativa inicial de OPEX (opcional)
* Observações da estimativa

Estas informações terão apenas caráter referencial.

Os valores oficiais do projeto serão definidos exclusivamente durante o Estudo de Viabilidade.

---

## Riscos Iniciais

Permitir cadastrar múltiplos riscos contendo:

* Descrição
* Impacto
* Observações

Os riscos cadastrados serão reutilizados automaticamente no Estudo de Viabilidade.

---

# Geração do Documento

Ao selecionar **Gerar TAP**, a plataforma deverá:

* validar os campos obrigatórios;
* gerar o documento utilizando o template institucional;
* gerar versão do documento;
* armazenar o arquivo no projeto;
* registrar o histórico.

O usuário não poderá editar manualmente o documento gerado.

Toda alteração deverá ocorrer através do formulário da plataforma.

Uma nova versão será gerada automaticamente.

---

# Aprovação

Após gerar a TAP, a plataforma deverá:

* criar automaticamente a solicitação de aprovação;
* enviar o documento para o módulo Aprovações;
* atualizar o projeto para o status **TAP Pendente de Aprovação**;
* impedir avanço para a Viabilidade enquanto a TAP não for aprovada.

---

# Reprovação

Caso a TAP seja reprovada:

* registrar justificativa obrigatória;
* registrar histórico;
* devolver para edição;
* manter todas as versões anteriores.

---

# Aprovação

Quando a TAP for aprovada:

* registrar usuário aprovador;
* registrar data e hora;
* registrar parecer;
* atualizar histórico;
* desbloquear automaticamente o módulo Estudo de Viabilidade.

---

# Integração com o Estudo de Viabilidade

Ao criar um novo Estudo de Viabilidade, a plataforma deverá herdar automaticamente as seguintes informações da TAP:

## Identificação

* Nome do Projeto
* Área Solicitante
* Responsável
* Gerente do Projeto
* Data de abertura

## Contexto

* Descrição do Projeto
* Problema ou Oportunidade
* Objetivo
* Escopo Inicial
* Fora do Escopo
* Benefícios Esperados

## Stakeholders

Todos os Stakeholders cadastrados.

## Riscos

Todos os riscos cadastrados.

## Estimativa Financeira

Caso existam valores estimados na TAP:

* apresentar como Estimativa Inicial;
* permitir alteração durante a Viabilidade;
* nunca considerar esses valores como oficiais.

---

# Histórico

Toda ação deverá registrar:

* Usuário
* Data
* Hora
* Ação executada
* Documento gerado
* Versão
* Alterações realizadas

---

# Regras de Negócio

A TAP representa apenas a formalização inicial do projeto.

Todas as informações financeiras cadastradas nesta etapa possuem caráter estimativo.

Os valores oficiais somente passarão a existir após a aprovação do Estudo de Viabilidade.

Nenhum projeto poderá avançar para a etapa seguinte sem a aprovação da TAP.
